# Historical Demand Prediction Interface

## Overview

The prediction interface estimates total hourly bicycle rentals using an XGBoost regressor trained on the UCI Bike Sharing dataset (2011–2012). It combines a model estimate with a separate historical SQL comparison. It is not a live forecast, a calibrated prediction interval, or a station-level planning system.

## Inference contract

The public function `src.predict.predict_demand(**scenario)` accepts a date, hour, holiday flag, weather category, temperature in °C, humidity in percent and wind speed in km/h. The function validates the inputs via `scenario_features()`, applies the shared ten-column model feature contract, and returns a nonnegative estimate rounded to one decimal place. The saved model must have the expected feature names and be a trusted, locally generated artifact.

`src.predict.estimate_scenario(**scenario)` returns a structured record containing:

- `estimated_rentals`: optimized-model estimate in rentals/hour.
- `model`: `optimized_xgboost`.
- `historical_period`: source years, `2011–2012`.
- `scenario`: selected calendar and weather-category conditions.
- `historical_reference`: observations, historical mean, minimum and maximum.
- `reference_sample`: `no_matches`, `small_sample` or `available`.

The inference API uses `models/demand_xgb_optimized.joblib` generated by `python -m src.optimize`; it does not silently substitute a baseline model when the optimized artifact is absent. The original baseline artifact is preserved for comparison. Models loaded with `joblib` must be trusted.

## Matched historical reference

The SQL comparison calls `historical_reference()` with the user's **hour**, derived **working-day status**, and selected **weather category**. The database is populated from the official historical records. The reference does **not** filter on exact calendar date, temperature, humidity or wind speed; consequently the reference mean and model estimate answer different questions.

The interface reports the number of matching observations and the historical mean/range. Zero matching records means the mean is **unavailable**, not zero. A sample with fewer than 30 records is flagged as small; this threshold is a presentation heuristic, not a statistical guarantee.

The historical weather category 4 is extremely rare in the source dataset (three observations overall). That category requires particular caution when interpreting aggregates.

## User interface and errors

`app.py` provides a Gradio form and a Markdown result. Integer-like slider/dropdown inputs are validated without silently truncating fractional values. An invalid scenario, missing model, unavailable database or incompatible model feature contract produces an actionable error instead of a fabricated estimate. The unfinished AI-assistant tab is not displayed; agent tool calling is a separate, unimplemented integration.

## Reproducibility

From the activated environment in the project root:

```bash
python -m scripts.download_data
python -m src.db
python -m src.train
python -m src.optimize
python -m pytest -q
python app.py
```

The reference data and both serialized models are generated locally; raw data, models, reports and credentials are not committed to Git.

## Evaluation context

The optimized model had a recorded chronological holdout MAE of **88.445**, RMSE of **124.719** and R² of **0.6801**, compared with an unoptimized baseline MAE of **89.589**. These values describe performance on the 2012 historical holdout, not verified accuracy for present-day or future operating conditions. The holdout was inspected during the earlier baseline analysis and must not be treated as completely untouched.
